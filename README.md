# 聚會簽到

用 QR code 或人手登記聚會出席，自動記錄日期時間、遲到與簽退，最後一鍵匯出出席名單。

- 單一 Node.js 程序 ＋ SQLite 單檔資料庫，沒有雲端依賴，資料留在自己的電腦。
- 手機優先介面，現場用平板掃描，散場用電腦匯出。
- 三種簽到方式：聚會 QR 自助、工作人員掃個人 QR、名單人手點擊。

---

## 快速開始

需要 **Node.js 22 或以上**（[下載](https://nodejs.org/)）。

### Windows

雙擊 `start.bat`。第一次會自動安裝套件、建立資料庫，並在畫面印出管理員密碼。

### 命令列（任何系統）

```bash
npm install
npm run setup          # 建立資料庫 + 管理員帳號（密碼會印在畫面）
npm start              # http://localhost:3000
```

想先看有資料的畫面：

```bash
npm run seed -- --demo
```

會建立兩個示範聚會、8 人名單與幾筆簽到記錄。

### 登入

`npm run setup` 會建立管理員帳號：

- 名稱：`管理員`（可用 `.env` 的 `ADMIN_NAME` 改）
- 密碼：若 `.env` 有設 `ADMIN_PASSWORD` 就用它，否則由系統隨機產生並印出一次

忘記密碼：

```bash
npm run user -- reset 管理員
```

## 五分鐘走一遍

1. **新增聚會**：填名稱、日期、時間、地點。費用、名額、餐飲選項可以留空。
2. **貼 QR code**：聚會頁按「顯示 QR code」，投影或列印貼在入口。參加者用手機掃就會開自助簽到頁。
3. **準備名單**：名單頁可逐個加人，或「匯入 CSV」一次貼上幾十人。加完可以「列印個人 QR」印出卡紙。
4. **現場簽到**：平板開聚會 →「現場簽到」。鏡頭對準卡片 QR，或搜尋名字按一下。
5. **散場總結**：按「總結」，看出席率、遲到、停留時間，按「匯出 Excel」。

## 三種簽到方式

| 方式 | 誰操作 | 記錄的 `method` | 適合 |
|---|---|---|---|
| 聚會 QR 自助 | 參加者自己 | `qr_self` | 入口貼一張大 QR，排隊最快 |
| 掃個人 QR | 工作人員 | `qr_scan` | 有預先印卡片，逐個確認 |
| 人手點擊 | 工作人員 | `manual` | 沒帶卡、臨時到場 |

**個人 QR 卡**：名單頁 →「列印個人 QR」，一張 A4 印 9 張卡，每張有姓名、8 碼短碼與 QR。QR 內容是 `ATT:<隨機 token>`，不是網址；普通相機掃到只會顯示一行字，一定要在已登入的簽到頁才解析得到。

**掃不到怎麼辦**：簽到頁有「輸入 8 碼短碼」的欄位，打 `AB12CD34` 一樣可以簽到。

## 自助簽到頁

聚會 QR 指向 `/s/<token>`，參加者會見到：

- 聚會名稱、日期、時間、地點、備註（**內部備註不會顯示**）
- 「你的姓名或電話」搜尋框 → 揀自己 → 簽到
- 「不在名單上？」展開後填姓名／電話 → 直接加入並簽到

安全設計：

- 只做逐字搜尋，不會列出完整名單；候選人電話遮蔽成 `9123****`
- token 是 24 bytes 隨機值，重新產生後舊 QR 即時失效
- 名額滿了會擋住新的自助報名（工作人員仍可強制加人）
- 過了「報名截止」不能再自助新增（已報名者仍可簽到）
- 每個 IP＋聚會每分鐘最多 40 次操作

**自助簽退**：聚會設定開啟後，簽到完成頁會出現「我要先離開」，需要輸入電話後 4 碼。

## 遲到與簽退

- **遲到**：以聚會時區的開始時間為準，超過「遲到寬限」（預設 15 分鐘）就標記，並記下遲到幾分鐘。判定在簽到寫入時完成，之後改規則不會影響舊記錄。
- **簽退**：工作人員在名單／簽到頁按「簽退」，或參加者自助簽退。停留時間 = 簽退 − 簽到。
- 總結頁會分開列「已簽到未簽退」，活動進行中這是正常的。
- 簽錯了可以「撤銷簽到」或「撤銷簽退」，記錄會即時更新。

## 名單匯入 CSV

欄位順序：`姓名, 電話, 組別, 桌號, 餐飲, 備註`。

```csv
姓名,電話,組別,桌號,餐飲,備註
陳大文,91234567,A 組,1 號桌,葷,
李小明,62345678,A 組,1 號桌,素,不吃牛
王美玲,53456789,B 組,2 號桌,,
```

- 有標題列會自動辨識（也接受 `name`、`phone`、`group` 等英文欄名）；沒有標題列就按位置讀。
- 只有姓名是必需，其餘可留空。
- 匯入前會先預覽：顯示會新增幾人、已存在幾人（同名或同電話會略過）。
- 電話會正規化（去空白、`-`、括號），香港號碼比對時只看後 8 位，所以 `+852 9123 4567` 與 `91234567` 當同一個人。
- Excel 另存時選「CSV UTF-8」，中文才不會亂碼。

## 匯出

| 檔案 | 內容 |
|---|---|
| CSV | UTF-8 帶 BOM，Excel 直接開不亂碼。出席者在前、未出席在後 |
| Excel | 三個工作表：`出席`、`未出席`、`統計`（出席率、遲到、平均停留、應收／實收、餐飲分佈） |

欄位：姓名、電話、組別、桌號、餐飲、簽到時間、遲到、遲到分鐘、簽退時間、停留分鐘、簽到方式、已繳費、備註。
時間一律以聚會時區顯示。

## 手機、平板與相機（重要）

瀏覽器只准「安全來源」使用相機：`https://` 或 `http://localhost`。

三種做法，按現場情況選：

1. **在伺服器本機用 localhost**：最簡單，適合先驗收。平板就無法用鏡頭。
2. **區網 + HTTPS**（建議）：用 `mkcert` 產生憑證，把根憑證裝到平板上，然後在 `.env` 設：
   ```env
   TLS_CERT=./certs/cert.pem
   TLS_KEY=./certs/key.pem
   ```
   重新啟動就會變 `https://192.168.x.x:3000`。
3. **完全不用相機**：簽到頁永遠有「輸入 8 碼短碼」，打數字一樣可以簽到，只是慢一點。

> 手機連不到？檢查 Windows 防火牆是否放行 Node.js（專用網路），以及 `.env` 的 `HOST=0.0.0.0`。

## 部署與開機自動啟動

三種上線方式（VPS + Docker、PaaS、Cloudflare Tunnel）的完整步驟見 **[docs/deploy.md](docs/deploy.md)**；
用 Google Cloud 的話看 **[docs/deploy-gcp.md](docs/deploy-gcp.md)**（Compute Engine，不建議 Cloud Run）。

最快的一條路（VPS 已裝 Docker）：

```bash
cp .env.example .env      # 填 APP_BASE_URL 與 ADMIN_PASSWORD
docker compose up -d --build
```

單一程序，適合放在辦公室的 Windows 電腦或內網 Linux 主機。本專案沒有建置步驟，安裝完即可啟動：

```bash
npm install
npm run migrate
npm start
```

**Windows 開機自動執行**：工作排程器 → 建立工作 → 觸發程序「登入時」 → 動作「啟動程式」→ 程式 `C:\...\attendance\start.bat` → 起始於 `C:\...\attendance`。

**Linux（systemd）**：

```ini
[Unit]
Description=Gathering Check-in
After=network.target

[Service]
WorkingDirectory=/opt/attendance
ExecStart=/usr/bin/node --env-file=.env server.mjs
Restart=always

[Install]
WantedBy=multi-user.target
```

`.env` 常用設定：

```env
PORT=3000
HOST=0.0.0.0
DATA_DIR=./data
APP_BASE_URL=http://192.168.1.50:3000   # 填死可避免換 IP 後 QR 失效
ADMIN_NAME=管理員
ADMIN_PASSWORD=換成你自己的
```

## 備份與還原

資料庫就是一個檔案：`data/attendance.db`。

```bash
npm run backup
```

會在 `data/backups/attendance-YYYYMMDD-HHMMSS.db` 產生一致性快照（用 `VACUUM INTO`，連未合併的 WAL 內容都包含），並自動只保留最近 14 份。

**部署在 PaaS／托管主機、沒有 shell 時**：登入後到「帳號」頁按 **下載備份 .db**，同樣是 `VACUUM INTO` 產生的一致性快照，直接用瀏覽器下載。

**還原**：停止程式 → 把備份檔改名為 `data/attendance.db` → 刪除同目錄的 `attendance.db-wal`、`attendance.db-shm` → 重新啟動。

> 不要直接複製使用中的 `.db` 檔，可能拿到未寫入的狀態。

## 帳號與權限

### 新增職員（網站內操作，唔需要命令列）

1. 用管理員登入 → 右上角選單 **職員**
2. 在「新增職員」填名稱、選角色；密碼可以自己填，**留空會自動產生一組**
3. 按「新增」→ 畫面會顯示一次密碼，按「複製」交給對方（離開頁面後不會再顯示）

同一頁可以：

- **重設密碼**：產生新密碼並顯示一次，對方目前的登入會即時失效
- **停用／啟用**：停用會踢掉該帳號的登入，但保留他的簽到記錄（記錄仍可追查）

保護規則：不能停用自己；不能停用最後一個啟用中的管理員。

> 冇 shell 的環境（PaaS）一樣用得，全部在瀏覽器完成。忘記管理員密碼時才需要用命令列 `npm run user -- reset 管理員`。

### 角色差異

| 角色 | 可以做 |
|---|---|
| 管理員 `admin` | 建立／編輯／刪除聚會、重設 QR、管理名單、簽到、匯出、管理職員帳號 |
| 工作人員 `staff` | 查看聚會、管理名單、簽到／簽退、匯出 |

工作人員看不到「新增聚會」與「職員」選單，直接開網址亦會被擋（403）。

簽到記錄會存 `operator_user_id`，總結與名單都追得到是誰按的。自助簽到時為空。

登入狀態存在 httpOnly cookie，12 小時滑動過期。所有表單都有 CSRF token。

## 資料模型

```
users ──< sessions
users ──< checkins（operator，自助時為 NULL）
events ──< event_attendees >── attendees
events ──< checkins >── attendees        UNIQUE(event_id, attendee_id)
```

- `attendees`：全域人名庫，一個人建一次，可参加多場。
- `event_attendees`：本場名單＋場次資料（桌號、餐飲、繳費）。
- `checkins`：一人一場一列，含簽到、簽退、遲到、方式、操作者。
- 聚會日期時間存「當地日期＋當地時間＋時區」，簽到時刻存 UTC，顯示時換算。

詳細設計見 [`docs/plan.md`](docs/plan.md)。

## 人數與效能上限

名單本身**沒有硬性上限**，但有幾個實際限制：

| 項目 | 現時設定 | 說明 |
|---|---|---|
| 全域會員（人名庫） | 無上限 | SQLite 單檔，十萬列仍可運作 |
| 單場聚會名單 | 建議 2,000 人以內 | 名單頁一次載入全部，2,000 行約 1 MB；再多會變慢 |
| CSV 匯入 | 每次 1,000 人、5 MB | 超過就分批匯入，資料不會重複 |
| 聚會名額 | 1–100,000，可留空 | **只擋自助簽到**；工作人員仍可超額加人 |
| 自助簽到限流 | 180 次／分鐘／IP＋聚會 | 同一間辦公室的 Wi-Fi 共用 IP，太低會誤擋；可用 `PUBLIC_RATE_LIMIT` 調 |
| 同時簽到 | 單程序 SQLite，每筆約 1 ms | 三部平板、200 人陸續進場完全夠 |
| 搜尋結果 | 簽到頁 12 筆、公開頁 8 筆 | 只影響顯示，不影響實際名單 |

以你目前 200 人左右的聚會，全部都在安全範圍。如果將來單場超過 2,000 人，或者想名單分頁、欄位排序，跟我說，可以加。

## 疑難排解

| 症狀 | 原因與處理 |
|---|---|
| 雙擊 `start.bat` 出現一堆「不是內部或外部命令」 | 批次檔被存成 UTF-8／LF 行尾，中文 Windows（CP950）會把中文位元組連換行一齊鋸開。現版本已改為純 ASCII＋CRLF，中文交給 `scripts/launch.mjs`；若仍出現，改用 `npm start` |
| 掃描頁說無法開相機 | 用 `localhost` 或設定 HTTPS；或改用手動短碼 |
| 手機打不開網站 | 防火牆未放行、`HOST` 不是 `0.0.0.0`、或平板與電腦不在同一網段 |
| QR 掃到舊聚會 | 曾按「重新產生 QR」，舊連結已失效，重新貼新的 |
| 匯出的 Excel 中文亂碼 | 用 Excel 開 CSV 時選 UTF-8；或直接匯出 `.xlsx` |
| 簽到時間比實際快／慢 | 檢查伺服器系統時間與時區設定（建議開啟自動校時） |
| 重複簽到 | 系統會顯示原本時間，不會重複計數 |
| 忘記管理員密碼 | `npm run user -- reset 管理員` |

## 設計取捨

- **不引入框架與 bundler**：需求固定、頁面不多，少一層建置少一種壞法；改完存檔即生效。
- **費用存整數「分」**：避免浮點誤差，Excel 匯出不會出現 `128.99999`。
- **簽到簽退同一列**：查出席不必 join，代價是不支援「中途離場再進場」；用撤銷簽退補救。
- **靠資料庫 UNIQUE 防重複**：不靠「先查再寫」，兩個工作人員同時掃同一人也不會產生兩筆。
- **統計即時計算**：不另存統計表，避免數字與名單對不上。
